핸디 영상 플레이어

Unity Hub에서 Handy-Video-Player 저장소를 Unity 6000.3.28f1로 연다. Unity가 이 저장소의 Packages/에 동봉된 핸디 패키지를 설치한다.
핸디 연동 코드는 Handy-Device-Control-for-Unity 저장소의 Development~ 프로젝트에서 수정한다. 새 버전의 .tgz를 영상 플레이어의 Packages/에 넣고 manifest.json의 파일명을 갱신한다. .tgz와 manifest.json, Unity가 갱신한 packages-lock.json을 함께 커밋한다.
Unity에서는 Assets/Scenes/VideoPlayer/HandyPlayer.unity를 열어 실행한다. Windows용 앱은 HandyPlayer → Windows 빌드로 빌드한 뒤 Builds/HandyPlayer/HandyPlayer.exe를 실행한다. 다른 PC에서는 실행 파일과 같은 폴더의 데이터·런타임 파일이 함께 필요하다. 영상과 .funscript는 실행 후 지정한 로컬 폴더에서 읽는다.

펌웨어 4 Wi-Fi용 개발자 설정 (최초 한 번)
Handy 사용자 포털에서 영상 플레이어에 사용할 Handy REST API v3용 Application ID를 발급받는다.
Assets/Data/HandyConnection.asset을 선택하고 Inspector의 Application Id에 발급받은 값을 입력한다. 이 에셋은 영상 플레이어의 설정이다.

블루투스 직접 연결 (Windows x64 에디터·플레이어)
1. PC와 핸디의 블루투스를 켠다. 씬을 재생하고 기기 연결 탭에서 블루투스 직접 연결 → 기기 검색을 누른다.
2. 펌웨어 3 또는 펌웨어 4 레거시 모드는 The Handy, 펌웨어 4 일반 모드는 ohd_hw…로 표시된다. 기기가 여럿이면 주소로 구별해 내 핸디를 선택한다.
3. 연결 확인을 누른다. 일반 BLE에서는 모델과 펌웨어 버전을, 레거시 BLE에서는 기기가 응답한 이름과 연결 방식을 표시한다. 두 모드 모두 연결 확인 중에는 이동 명령을 보내지 않는다. 블루투스 연결에는 인터넷, Application ID, Connection Key가 필요 없다.

Wi-Fi 연결
1. 처음 한 번 핸디에 Wi-Fi를 등록하면 설정 앱과 웹페이지는 닫아도 된다. 핸디 1의 펌웨어 3은 전원을 켠 뒤 Wi-Fi 버튼을 한 번 짧게 눌러 온라인 모드로 전환한다. 펌웨어 4는 Handy Onboarding 앱의 Advanced → Boot mode에서 WiFi를 선택하면 다음부터 전원을 켤 때 자동으로 연결된다.
2. 씬에서 Wi-Fi 연결을 선택하고 자기 기기의 Connection Key를 입력한다. 입력한 문자는 그대로 보이고, 키는 실행 중 메모리에만 보관한다.
3. 연결 확인을 누르면 온라인 여부와 펌웨어를 조회한다. 펌웨어 3은 REST API v2, 펌웨어 4는 REST API v3를 사용한다. 펌웨어 3에는 Application ID가 필요 없다. 기기 확인 중에는 모터 명령을 보내지 않는다.

2초 동작과 정지 (두 연결 방식 공통)
1. 준비 완료 후 2초 테스트 시작을 누른다. 펌웨어 4 Wi-Fi와 일반 BLE는 HAMP 속도 10%, 설정된 이동 범위의 40~60%를 사용한다. 일반 BLE의 구간 설정은 4.0.15부터 지원한다. 펌웨어 3 Wi-Fi와 레거시 BLE는 40% → 60% → 40% 위치를 이동당 0.5초로 요청한다. 통신이 늦어 시험 시간을 넘길 이동은 생략한다.
2. 정지 버튼, 포커스 상실 또는 시험 종료 시 펌웨어 3 Wi-Fi는 후속 위치 전송을 취소한다. 전송 중인 요청이 끝나면 같은 v2 연결로 왕복 모드를 선택하고 정지 명령을 보낸 뒤 정지 상태를 조회한다. 펌웨어 4의 Wi-Fi와 일반 BLE는 왕복 모드에서 정지를 요청한 뒤 상태를 조회한다.
3. Wi-Fi와 일반 BLE는 정지 확인을 표시한다. 레거시 BLE는 마지막 이동 시간이 지난 뒤 기기 응답을 확인하고 위치 명령 전송 종료를 표시한다. 실제 모터 정지를 확인한 뒤 Play 모드를 종료한다. 정지 미확인이 뜨면 기기 버튼으로 멈추고 같은 기기의 연결을 복구한 뒤 정지를 다시 누른다.

로컬 영상과 스크립트 테스트
1. HandyPlayer 씬을 열고 Play를 누른다. 영상 목록 탭에서 기본 폴더 E:\보안과 그 하위 폴더의 영상을 찾는다. 다른 폴더를 쓰거나 파일을 추가했다면 영상 폴더를 입력하고 새로고침을 누른다.
2. 영상 검색에 파일명이나 폴더명 일부를 입력하거나 목록을 스크롤하고, 원하는 썸네일을 누른다. 미리보기 없음이 표시된 영상도 제목을 눌러 선택할 수 있다. 같은 폴더의 같은 이름을 짝으로 쓴다. 예를 들어 장면.mp4에는 장면.funscript가 필요하다. 짝이 없는 영상에는 스크립트 없음이 표시된다.
3. 블루투스 또는 Wi-Fi로 연결 확인을 마치고 영상과 핸디 재생을 누른다. Unity에서 영상과 소리가 재생된다. 동작은 영상의 현재 시간에 맞춘다. 첫 동작이 늦은 파일은 재생 전에 첫 동작으로를 눌러 해당 위치로 이동할 수 있다.
4. 일시정지는 현재 영상 위치를 보존하고 기기 정지를 요청한다. 기기가 준비 완료로 돌아오면 재생 위치 슬라이더로 옮긴 뒤 이어서 재생할 수 있다. 정지 버튼은 영상을 처음으로 되돌린다. 영상 종료, 재생 오류, 창 비활성화와 씬 종료 시에도 기기 전송을 중단한다.
5. 펌웨어 4 일반 BLE와 Wi-Fi는 짧은 분량의 시간·위치 목록을 기기에 미리 보내고 영상 시간으로 시계를 보정한다. 펌웨어 3 Wi-Fi와 레거시 BLE는 유한한 위치 이동을 차례로 보낸다. 통신이 늦으면 지난 위치를 건너뛰므로 빠른 구간은 특히 펌웨어 3 Wi-Fi에서 단순해질 수 있다.
6. 영상과 .funscript 원본은 지정한 로컬 폴더에서 읽는다. Wi-Fi 연결은 제조사 서버로 재생에 필요한 시간·위치와 기기 제어 요청을 전송한다.
7. Windows용 영상 플레이어에 libmpv 디코더가 포함돼 있다. HEVC(H.265) MP4나 MKV도 썸네일을 고르면 원본의 첫 화면을 열고, 재생 중 필요한 부분을 읽는다. FFmpeg나 Windows HEVC 확장 설치, 파일 전체 변환은 필요 없다. 스크립트는 원본 영상의 재생 시간을 따른다.
8. 크게 보기를 누르면 목록이 접히고 영상 영역이 넓어진다. 기본 보기 또는 Esc로 목록에 돌아온다. 보기를 바꿔도 재생 위치와 핸디 연결은 유지되며, 아래쪽 정지 버튼을 계속 사용할 수 있다.

Windows BLE 구현
Handy-Device-Control-for-Unity 저장소의 Package/Runtime/HandyBleNative.cs가 Windows BLE 검색과 GATT 구독·쓰기를 담당한다. 같은 폴더의 WindowsRuntime.cs는 Windows에 포함된 WinRT 함수를 호출하고, WindowsBluetoothEvent.cs는 알림과 연결 끊김을 C#으로 받는다.
Windows x64 에디터와 플레이어 모두 Windows에 포함된 combase.dll과 ole32.dll을 사용한다.
